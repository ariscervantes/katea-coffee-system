# Seguridad: OWASP API Security Top 10 (2023) en Katea

Esta tabla compara cada riesgo del [OWASP API Security Top 10, edición 2023](https://owasp.org/API-Security/editions/2023/en/0x11-t10/) con lo que hace hoy el código de Katea. Solo se afirma lo que se puede ver en el repositorio.

Estado: **Cubierto** (hay una defensa en el código para el caso que aplica a Katea), **Parcial** (hay defensas, pero falta alguna pieza importante) o **No cubierto**.

| Riesgo | Qué hace Katea | Dónde (archivo y función) |
|---|---|---|
| **API1:2023 Broken Object Level Authorization** | **Cubierto.** Un cliente solo puede leer o borrar sus propios pedidos: el `usuario_id` sale del token y se añade como filtro `AND usuario_id = %s` en el SQL. Un pedido ajeno responde 404 igual que uno inexistente, para no revelar que existe. Solo el rol `admin` usa las consultas sin filtro. | `app/repositorios/pedidos.py` → `_listar`, `_obtener`, `_eliminar`, `_desde_fila`; `app/servicios/pedidos.py` → `ve_todos`, `consultar_pedido`, `eliminar_pedido`; `app/routers/pedidos.py` → `consultar`, `eliminar` |
| **API2:2023 Broken Authentication** | **Parcial.** Claves guardadas con bcrypt (costo 12) y nunca en claro. Si el usuario no existe se compara igual contra un hash ficticio y el mensaje es el mismo ("Usuario o clave incorrectos"), para no revelar qué cuentas existen. JWT HS256 con algoritmo fijo al verificar, `sub`, `rol`, `iat` y `exp` obligatorios, vigencia de 30 minutos y secreto de al menos 32 bytes leído del entorno. **Falta:** límite de intentos de login (fuerza bruta) y revocación de tokens (no hay cierre de sesión ni lista de tokens revocados; un token robado vale hasta que expira). | `app/seguridad.py` → `proteger_clave`, `comprobar_clave`, `_hash_ficticio`, `Autenticacion.iniciar_sesion`, `crear_token`, `verificar_token`, `secreto_desde_entorno`, `usuario_actual` |
| **API3:2023 Broken Object Property Level Authorization** | **Cubierto.** Los modelos de entrada usan `extra="forbid"`: el cliente no puede mandar `usuario_id`, `total`, `precio_unitario` ni `estado` (asignación masiva); la API los calcula. Las respuestas pasan por `response_model`, así que nunca sale `clave_hash` ni otro dato del usuario; además `clave_hash` y `clave` tienen `repr=False` para no aparecer en logs. | `app/modelos/pedidos.py` → `PedidoEntrada`, `ProductoPedidoEntrada`, `EntradaPedidosComentario`, `Pedido`; `app/modelos/productos.py` → `ProductoEntrada`; `app/seguridad.py` → `Credenciales`; `app/repositorios/usuarios.py` → `Usuario` |
| **API4:2023 Unrestricted Resource Consumption** | **Parcial.** Hay topes de tamaño en los campos de texto (nombre 80, descripción 200, comentario 300, clave 1024), en `cantidad` e IDs (≤ 4 294 967 295) y en el total del pedido. Las llamadas a Gemini tienen timeout por intento y un solo reintento; la conexión a MySQL tiene `connect_timeout=5`. **Falta:** límite de peticiones por minuto (por IP o por usuario), tope en el número de elementos de `productos` en un pedido, paginación en `GET /productos` y `GET /pedidos`, y protección del login, donde cada intento cuesta un cálculo bcrypt. | `app/modelos/productos.py` → `Nombre`, `Descripcion`; `app/modelos/pedidos.py` → `Id`, `Cantidad`, `Comentario`, `PedidoEntrada`; `app/servicios/pedidos.py` → `sumar_al_total`, `MAX_IMPORTE`; `app/integraciones/gemini.py` → `preguntar_a_la_ia`, `_timeout_desde_entorno`; `app/db/conexion.py` → `BaseDatos.conexion` |
| **API5:2023 Broken Function Level Authorization** | **Cubierto.** Crear, reemplazar y borrar productos exigen rol `admin` (401 sin token, 403 con rol cliente). El acceso global a pedidos solo se activa si el rol del token es `admin`; el rol viene del JWT firmado y se valida contra `admin`/`cliente`. | `app/seguridad.py` → `exigir_admin`, `verificar_token`; `app/routers/productos.py` → `crear_producto`, `reemplazar_producto`, `eliminar_producto` (con `Depends(exigir_admin)`); `app/servicios/pedidos.py` → `ve_todos` |
| **API6:2023 Unrestricted Access to Sensitive Business Flows** | **Parcial.** Crear un pedido exige sesión, el precio sale de la base de datos y no del cliente, y el producto debe existir y estar disponible (bloqueo `FOR UPDATE` dentro de una transacción). **Falta:** nada impide automatizar `POST /pedidos` o `POST /pedidos/comentario` (este último gasta cuota de Gemini): no hay límite de peticiones ni clave de idempotencia en `POST /pedidos`, así que reenviar la misma petición crea pedidos duplicados. | `app/repositorios/pedidos.py` → `RepositorioPedidos.crear`; `app/servicios/pedidos.py` → `precio_de_compra`, `crear_pedido`; `app/routers/pedidos.py` → `crear`, `comentario` |
| **API7:2023 Server Side Request Forgery** | **Cubierto.** La API no descarga ninguna URL que mande el cliente. `imagen_url` solo se valida (extensión de imagen, sin saltos de línea) y se guarda como texto. La única petición saliente es a la IA y su URL viene de la variable de entorno `EXTERNO_URL`, nunca de la petición. | `app/modelos/productos.py` → `ProductoEntrada.validar_imagen`; `app/integraciones/gemini.py` → `IA_URL`, `preguntar_a_la_ia` |
| **API8:2023 Security Misconfiguration** | **Parcial.** CORS con lista explícita de orígenes (nunca `*`), métodos y encabezados limitados. Los errores no controlados responden un 500 genérico y el detalle solo va al log; los errores de validación no devuelven el valor enviado. Los secretos se leen del entorno, `.env` está en `.gitignore` y `.env.example` solo trae marcadores. MySQL se publica solo en `127.0.0.1` y la API usa un usuario distinto de root. **Falta:** `/docs` y `/redoc` están siempre activos (también en producción), la API corre en HTTP sin TLS (no hay proxy HTTPS configurado) y no se envían encabezados de seguridad como `Strict-Transport-Security`. | `app/main.py` → `crear_app` (`CORSMiddleware`); `app/errores.py` → `registrar_manejadores` (`error_validacion`, `error_interno`); `app/seguridad.py` → `secreto_desde_entorno`; `.env.example`; `compose.yaml` |
| **API9:2023 Improper Inventory Management** | **Cubierto, con límites.** Todas las rutas están en el contrato OpenAPI que genera FastAPI, exportado a `docs/openapi.json`, y la versión de la API está declarada (1.0.0, con CHANGELOG). No hay rutas viejas ni ocultas fuera del contrato. **Límites:** las rutas no llevan prefijo de versión (`/v1`) y no hay una prueba que avise si `docs/openapi.json` se queda desactualizado. | `app/main.py` → `crear_app` (`FastAPI(version="1.0.0")`); `scripts/generar_contrato.py` → `main`; `docs/openapi.json`; `CHANGELOG.md` |
| **API10:2023 Unsafe Consumption of APIs** | **Cubierto.** La respuesta de Gemini se trata como no confiable: se valida que sea un objeto con `sentimiento` dentro de tres valores permitidos y `respuesta` como texto no vacío, recortado a 200 caracteres; cualquier otra forma responde 502. Hay timeout por intento (504), un solo reintento y solo ante 429/5xx, y la clave va en un encabezado y se lee del entorno (sin ella, 503). Los datos del cliente que se mandan a la IA salen del token, no del cuerpo. | `app/integraciones/gemini.py` → `preguntar_a_la_ia`, `_fallo_transitorio`; `app/servicios/pedidos.py` → `validar_respuesta_ia`; `app/modelos/pedidos.py` → `RespuestaComentario`; `app/routers/pedidos.py` → `comentario`, `datos_del_cliente` |

## Inyección SQL

No es un riesgo propio del Top 10 de APIs (está en el Top 10 web), pero conviene dejarlo claro: todas las consultas usan marcadores `%s` de PyMySQL y los datos del cliente nunca se concatenan al SQL (`app/repositorios/productos.py`, `app/repositorios/pedidos.py`, `app/repositorios/usuarios.py`).

## Pendientes conocidos

- **Límite de peticiones por minuto:** no existe en ninguna ruta. Afecta sobre todo a `POST /login` (fuerza bruta y costo de bcrypt), `POST /pedidos` y `POST /pedidos/comentario` (cuota de Gemini). Riesgos API2, API4 y API6.
- **Revocación de tokens JWT:** no hay cierre de sesión ni lista de tokens revocados; un token vale hasta su `exp` (30 minutos). Riesgo API2.
- **Clave de idempotencia en `POST /pedidos`:** reenviar la misma petición crea otro pedido. Riesgo API6.
- **Topes de volumen:** sin límite de elementos en la lista `productos` de un pedido y sin paginación en `GET /productos` ni `GET /pedidos`. Riesgo API4.
- **Configuración de producción:** `/docs` y `/redoc` siempre activos, sin HTTPS y sin encabezados de seguridad. Riesgo API8.
- **Inventario:** sin prefijo de versión en las rutas y sin prueba que compare `docs/openapi.json` con el contrato actual. Riesgo API9.
