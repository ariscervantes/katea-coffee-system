# Preparar y ejecutar U3S4 en equipo

## Instalación y configuración de desarrollo

Desde la raíz del repositorio, usar Python 3.14 (versión comprobada) y un MySQL 8
propio de desarrollo. No apuntar a una base de otro proyecto.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check
if [ ! -f .env ]; then cp .env.example .env; fi
chmod 600 .env
```

Si `.env` ya existe, conservarlo y completar únicamente las variables nuevas.
En el editor, completar DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME y
MYSQL_ROOT_PASSWORD con valores propios. Compose publica por defecto
127.0.0.1:13306; DB_PORT debe coincidir. Para la semilla manual establecer
KATEA_ENTORNO=desarrollo. No usar contraseñas personales.

Generar JWT_SECRETO sin imprimirlo ni ponerlo en el historial. Este comando
conserva un secreto existente y reemplaza únicamente un marcador o valor corto:

```bash
python - <<'PY'
from pathlib import Path
from secrets import token_urlsafe
from dotenv import dotenv_values, set_key
ruta = Path('.env')
actual = dotenv_values(ruta).get('JWT_SECRETO') or ''
if len(actual.encode('utf-8')) < 32 or actual.startswith('REEMPLAZAR'):
    set_key(ruta, 'JWT_SECRETO', token_urlsafe(48))
ruta.chmod(0o600)
PY
```

Variables exportadas en la terminal prevalecen sobre `.env`; comprobar que
apunten al mismo entorno. Conservar JWT_SECRETO entre reinicios.

```bash
docker compose up -d --wait mysql
docker compose ps
python scripts/crear_usuarios_desarrollo.py
```

Compose inicializa base y usuario solo en un volumen nuevo; no actualiza claves
de cuentas existentes. No eliminar volúmenes para cambiar una contraseña.
La semilla manual solicita y confirma claves sin eco para dev_admin (admin),
dev_cliente1 y dev_cliente2 (cliente); guarda solo hashes bcrypt. Si algún nombre
existe, revierte las tres inserciones sin sobrescribirlo: reutilizar sus claves
locales conocidas. No se crean cuentas al arrancar la API.

## API y producto soporte

En una terminal dedicada, con el entorno virtual activado:

```bash
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

El arranque crea las tablas ausentes. Abrir http://127.0.0.1:8000/docs, hacer
POST /login con dev_admin y su clave local, y pegar el access_token en Authorize.
No publicar el token ni capturar el diálogo de autorización con el valor visible.

Crear por POST /productos un soporte distinto de Latte y Capuccino, que son los
nombres usados por la plantilla para el CRUD del profesor:

```json
{
  "nombre": "U3S4 soporte pedidos",
  "descripcion": "Producto disponible para las pruebas de pedidos",
  "precio": 25.10,
  "imagen_url": "soporte.png",
  "disponible": true,
  "preparacion": "no_aplica"
}
```

Anotar su ID real. Si ya existe, localizarlo con GET /productos y comprobar que
siga disponible; reutilizarlo. Conservarlo durante ambas corridas. No usar el ID
de un producto que el script cree y borre: la prueba 20 necesita un producto
preexistente y la FK de pedidos impide borrar productos referenciados.

## Configuración personal ignorada

En otra terminal, desde la misma raíz del repositorio:

```bash
if [ ! -f prueba_U3S4.local.json ]; then
  cp prueba_U3S4.example.json prueba_U3S4.local.json
fi
chmod 600 prueba_U3S4.local.json
```

Editar únicamente la copia local:

- matricula: matrícula propia de ocho dígitos, como texto.
- base: URL/puerto de la API de desarrollo.
- auth.admin, auth.usuario y auth.otro: claves locales de las tres cuentas.
  Mantener el orden usuario, clave: el script altera el último campo para probar
  un login incorrecto. Los dos clientes deben ser personas de prueba distintas.
- propio.valido.productos[0].producto_id: ID numérico del soporte disponible.
  El 1 de la plantilla es ilustrativo, no garantiza que exista ese producto.

No cambiar prueba.json para U3S4 ni versionar la copia local. La plantilla
compartida tiene marcadores sin credenciales utilizables. Las claves en el JSON
local son necesarias para que el script haga login; no compartir ese archivo.

## Dos corridas con reinicio

El script auténtico está versionado como probar_api_U3S4.py y acepta la ruta JSON
como primer argumento. No necesita dependencias adicionales: usa HTTP y la
biblioteca estándar. Sus mensajes internos conservan el nombre probar_api.py
que puso el profesor; usar los comandos de esta sección.

```bash
python probar_api_U3S4.py prueba_U3S4.local.json
```

Guardar la salida completa y copiar el reporte_U3S4 generado a una carpeta
personal bajo evidencias/ antes de la segunda corrida. El reporte se sobrescribe
al repetir: usar nombres o carpetas distintas por ronda. Primera corrida limpia:
19/20, con la prueba 15 pendiente.

En la terminal de Uvicorn, Ctrl+C; esperar la detención y ejecutar otra vez el
mismo comando de Uvicorn. No reiniciar MySQL ni cambiar base, soporte,
configuración o directorio de trabajo. No eliminar `.persistencia_U3S4_*.json`.
Volver a ejecutar, desde la misma raíz:

```bash
python probar_api_U3S4.py prueba_U3S4.local.json
```

Guardar segunda salida completa y reporte por separado; resultado esperado
20/20. La prueba 15 usa el estado previo; 19 exige 403 al cliente y 20 espera
404 para el pedido ajeno y 200 para el dueño. El script consume el archivo de
estado en esta segunda ejecución. El reinicio real debe documentarse aparte:
el script por sí solo no comprueba que haya cambiado el proceso.

Si una corrida falla, revisar la causa antes de repetir y respaldar cada intento;
no borrar el estado indiscriminadamente ni alterar el script. Pedidos con soporte
inexistente en el cuerpo dan 422; pedidos ajenos o inexistentes en rutas dan 404.

## Contrato y comprobaciones propias

```bash
PYTHONDONTWRITEBYTECODE=1 python -m pytest -q -p no:cacheprovider
python scripts/generar_contrato.py
git diff -- docs/openapi.json
```

La suite propia no usa MySQL real. La integración MySQL y las dos corridas
registradas anteriormente son resultados previos, no una ejecución nueva de cada
integrante. Cada integrante debe tomar sus capturas reales de /docs y del
resultado completo, sin contraseñas ni tokens. Revisar `git diff --cached`
antes de compartir cambios: no incluir .env, configuración local ni evidencias.
